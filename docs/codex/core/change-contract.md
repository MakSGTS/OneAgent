# Change Contract

Print a Change Contract before implementation. Use it to make scope, risk, and
validation explicit.

## Required sections

- Goal
- Files to create
- Files to modify
- Files not to modify
- Behavioral impact
- Risks
- Validation commands
- Suggested commit message

Use exact repository-relative file paths when they can be determined. State when
no files are expected for a section.

Acknowledge pre-existing working tree changes and explain how they will be
preserved.

Printing the Change Contract does not require waiting for user confirmation
unless the user explicitly requested a review-only phase or explicit approval
before edits.
